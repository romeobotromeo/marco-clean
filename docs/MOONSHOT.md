# MOONSHOT

## Marco is on-demand help for real estate professionals

Marco connects real estate professionals with RUNNERS: on-demand staff who can help agents get practical work done. Josh’s shorthand is “DoorDash for real estate professionals.” An agent asks for help; Marco understands the job, finds an available runner, coordinates the work, and keeps the agent informed.

MARCO Outreach is the communication channel, not the entire business. Listing campaigns bring agents into conversations. Over time, the same assistant can become the place they turn when they need reliable help with a property or a transaction-related task.

## The starting point

Josh originally built Marco around runners and tested the service on Render. A small runner database already exists. The current app contains runner recruitment, application and operations code; preserve and assess that foundation before replacing it. A database entry does not by itself establish current availability, qualifications or readiness for dispatch.

The immediate build is the Angus campaign: cloud messaging, clear progress monitoring, and a useful property assistant. This is the first working channel, not proof that the runner marketplace is already operating.

## The experience we want

An agent texts Marco with a task. Marco asks only what is needed to understand the location, timing, access requirements and work involved. The agent sees the scope and price before committing. An eligible runner accepts the work, receives the approved instructions, provides progress updates and confirms completion. The agent has one clear place to ask questions or resolve an issue.

Potential task categories to validate with agents include property preparation, meeting vendors, access coordination and open-house support. Define the permitted scope of each task before offering it; do not assume a runner can perform licensed real estate work or any activity requiring credentials they do not have.

## Marco’s character

Marco is polite, practical and plainspoken, with the sensibility of a smart mechanic. He knows the work, asks useful questions and does not bluff. He introduces himself as an automated assistant working on Josh’s behalf. He never pretends to be Josh.

## Build in stages

1. **Angus first:** verified property answers, contextual outreach explanations, opt-outs, human handoff, live dashboard and reliable cloud sending. Josh confirms the test before any test message, then approves bulk separately.
2. **Campaign views:** separate campaigns, audiences, facts, approvals and results. Preserve contact history and suppression across campaigns.
3. **Runner service pilot:** review the existing runner roster; confirm availability and capabilities; define a narrow service area, job types, pricing and a human-supervised dispatch process.
4. **Dispatch product:** agent requests, runner acceptance, availability, assignment, arrival/work/completion status, payment and issue handling.
5. **Repeatable operations:** improve fulfillment quality, repeat use and economics before expanding geography or task scope.

Listing mode and runner-service mode must remain distinct. Someone asking about Angus should not unexpectedly enter a staffing pitch or a different property conversation.

## Decisions before a runner pilot

- Which agents and neighborhood form the first service area?
- Which one or two jobs are requested often enough to support repeat use?
- Which existing runners are still active and suitable for those jobs?
- How are scope, price, pay, cancellations and completion evidence handled?
- What access, qualification, insurance and responsibility requirements apply to each job?
- When does Marco coordinate automatically, and when does Josh intervene?

These are decisions to resolve, not commitments already made.

## Learn from every campaign and job

Save a short review after each run: what was requested, what happened, timing, cost, confusing messages, exceptions and owner feedback. Turn observed failures into specific fixes and regression tests. Measure whether each release improves the experience before expanding automation.

For outreach, track delivery, meaningful replies, opt-outs and estimated link engagement. For runner services, track request-to-acceptance time, fulfillment, completion quality, repeat agent use and unit economics. A growing contact list alone is not marketplace traction.
